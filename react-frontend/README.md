# dexMonitor React Frontend

This is the React/Vite dashboard for `dexMonitor`.

The frontend is an operator interface for live DEX offers, historical offer analysis, account and secret administration, snapshot logs, MM controller transactions, and trade-cost/premium views.

## Tech Stack

- React
- TypeScript
- Vite
- Playwright for end-to-end tests
- The Go server in `../cmd/server` serves the production build

## Development

Install dependencies:

```bash
npm install
```

Run the Vite dev server:

```bash
npm run dev
```

For full behavior, keep the backend and supporting services running from the parent repository:

```bash
docker compose up --build -d
```

## Build

```bash
npm run build
```

The production output is written to `dist/`. The Go server reads this directory through `FRONTEND_DIR`, which defaults to `./react-frontend/dist` in local development and `/app/react-frontend/dist` in the container.

## Tests

Run Playwright tests:

```bash
npm run test:e2e
```

When a backend is already running and you do not want Playwright to start its own server:

```bash
PLAYWRIGHT_SKIP_WEBSERVER=1 npm run test:e2e -- --project=chromium
```

## Backend API Expectations

The UI expects the monitor server to expose endpoints such as:

- `/api/live_offers`
- `/ws/live_offers`
- `/api/past_offers`
- `/api/past_order_stats`
- `/api/general_stats/overview`
- `/api/snapshot-log`
- `/api/payment_method_groups`
- `/api/trade_cost_config`
- `/api/mm-controller/transactions`
- `/api/trading/accounts`

Most data ultimately comes from the shared Postgres database and from the unified API/snapshot services in the parent Compose stack.

## Notes

- Do not edit files in `dist/` by hand; they are generated by `npm run build`.
- Keep UI assumptions aligned with `dexMonitor/cmd/server/main.go` and the API handler tests.
- Prefer adding typed API response shapes in `src/types.ts` when new dashboard panels need data from the server.
